# Career Orientation Model Card

## Overview

This model predicts the most suitable career path for a student based on their skills, interests, academic performance, and goals. It powers the `/api/career/predict` endpoint and the multi-step career assessment wizard in the student dashboard.

---

## Model Architecture

| Component | Details |
|-----------|---------|
| **Encoder** | `sentence-transformers/all-MiniLM-L6-v2` (384-dim, mostly frozen) |
| **Classifier Head** | 3-layer MLP: 384 → 256 → 128 → 6 |
| **Activations** | BatchNorm + ReLU + Dropout (0.3 / 0.2) |
| **Output** | Softmax over 6 career classes |
| **Total Parameters** | 22,846,214 (3,681,926 trainable, 19,164,288 frozen) |
| **Model Size** | ~87 MB |

### Input Format

Student profiles are serialized to a fixed text template before encoding:

```
Skills: python, machine learning, data analysis.
Interests: AI research, statistics.
Projects: Built a sentiment classifier. Analyzed sales data.
Goals: target fintech, salary 55000, remote hybrid.
Academic: Math 18/20, Sciences 16/20, Languages 12/20, Arts 8/20.
```

## Training

### Dataset

| Property | Value |
|----------|-------|
| Total profiles | 1,200 |
| Profiles per class | 200 (balanced) |

### Hyperparameters

| Parameter | Value |
|-----------|-------|
| Epochs (max) | 40 |
| Early stopping patience | 8 |
| Batch size | 32 |
| Head learning rate | 2e-4 |
| Encoder learning rate | 5e-6 (differential) |
| Weight decay | 1e-4 |
| Label smoothing | 0.1 |
| Gradient clipping | max_norm = 1.0 |
| LR scheduler | ReduceLROnPlateau (factor=0.5, patience=3) |
| Unfrozen encoder layers | Last 2 transformer layers |

### Training Environment

- Framework: PyTorch
- Device: CPU / CUDA (auto-detected)
- Data split: 70% train / 15% val / 15% test (stratified)

| Software Engineering | 1.00 | 0.47 | **0.64** | 30 |
| UX/UI Design | 0.97 | 0.97 | **0.97** | 30 |
| Web Development | 0.64 | 0.93 | **0.76** | 30 |
| **Macro avg** | 0.76 | 0.73 | **0.72** | 180 |

### Notable Observations

- **UX/UI Design** is the easiest class to distinguish (F1 = 0.97) — its skill/interest profiles are distinctive
- **Data Science** has the weakest performance (F1 = 0.42) — heavily confused with AI/ML and Business Analytics due to overlapping skill sets
- **Software Engineering** has perfect precision (1.00) but low recall (0.47) — when the model predicts SE it's always right, but it misses many SE profiles
- Model did not reach the 85% target accuracy

## Possible Improvements for Higher Accuracy

### Data Quality & Quantity (highest impact)

1. **More data for Data Science** — Add 200–400 more profiles that clearly differentiate Data Science from AI/ML (focus on business context, domain analysis, SQL, visualization rather than neural networks).
2. **Real-world profiles** — Supplement synthetic Gemini-generated data with real LinkedIn/GitHub profiles to reduce distribution shift.
3. **Data augmentation** — Apply synonym substitution, LLM-based paraphrasing, or skill permutation to expand the effective training set.

### Model Architecture

4. **Larger encoder** — Replace `all-MiniLM-L6-v2` (384-dim) with `all-mpnet-base-v2` (768-dim) for richer semantic representations; expect +3–5% accuracy at ~3× inference cost.
5. **Contrastive / triplet loss** — Add a metric learning objective alongside cross-entropy to push embeddings of different classes further apart, especially helpful for the AI/ML vs Data Science boundary.
6. **Ensemble** — Combine the PyTorch classifier with a logistic regression trained on Gemini embedding features; ensembles typically add +2–4% accuracy.

### Training

7. **Unfreeze more encoder layers** — Try unfreezing the last 4 layers instead of 2 with a very small LR (1e-6) for better domain adaptation.
8. **Mixup / label mixing** — Apply mixup augmentation in embedding space to smooth the decision boundary.
9. **Focal loss** — Replace cross-entropy with focal loss to down-weight easy examples and focus training on hard cases (especially Data Science vs AI/ML boundary).

### Post-processing

10. **Confidence calibration** — Apply temperature scaling on the softmax output so that confidence percentages better reflect true probability, making the career UI more trustworthy.
11. **Threshold tuning** — Set class-specific thresholds rather than argmax; useful for returning "unsure" when top confidence is below e.g. 40%.

## Integration

The model is served via FastAPI with lazy loading (loads on first prediction, stays in memory):

```
POST /api/career/predict   → CareerPredictionResponse
GET  /api/career/status    → {"model_available": true, "careers": [...]}
GET  /api/career/careers   → list of career labels
```

Rate limited to **15 requests/minute per user**.
